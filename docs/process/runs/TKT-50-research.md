## Problem Framing
Currently, the LangGraph "Pilot" nodes are mock functions. To achieve the project goal of an autonomous trading agent system, these nodes must be replaced with real AI-driven reasoning capable of:
1. Understanding roles (PM, Research, Architect).
2. Utilizing project-specific "Skills" (Workflows).
3. Accessing external tools (MCP servers).

## Existing Approaches
1. **Hardcoded Prompts**: Low flexibility, hard to maintain.
2. **Dynamic Prompting (Recommended)**: Loading agent personalities from Markdown (`docs/agents/`) and skills from (`docs/skills/`). This ensures documentation and code are always in sync.

## Options & Trade-offs
| Option | Pros | Cons |
|--------|------|------|
| **V1: Basic Chat** | Simple to implement. | No tool access, limited roles. |
| **V2: Agent Factory + Skills** | Full role support, dynamic scaling. | Requires complex parsing and context injection. |
| **V3: Full MCP Integration** | Agents can use terminal/filesystem/git tools. | High complexity, requires robust error handling. |

## Recommendation
Implement **Option 2 (Agent Factory + Skills)** as the baseline for Phase 7. Integrate LangChain's `ChatPromptTemplate` to inject agent definitions directly into the system prompt. Use the existing Redis checkpointing for state persistence.

## Risks
- **Token Usage**: Agents might loop if not gated.
- **Context Window**: Large skill/agent documentation might bloat tokens.
- **Process Violation**: Agents might attempt mutations without Git preflight if not strictly constrained in the prompt.
